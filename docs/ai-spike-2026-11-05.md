# BiRefNet Spike

Measured 2026-11-05 on:

- AMD Ryzen 9 9950X, 16 cores / 32 threads
- 93.5 GiB physical memory
- rembg 2.0.86
- onnxruntime 1.31.1
- CPUExecutionProvider

The sample was a generated 1024x1024 synthetic ellipse. These numbers measure
runtime cost only. They do not establish segmentation quality on plant tissue.

## Results

| Measurement | First run | Cached-weight run |
| --- | ---: | ---: |
| Session load | 151.717 s, includes 973 MiB download | 4.939 s |
| Inference runs | 3 | 5 |
| Warmup runs | 1 | 1 |
| p50 inference | 6.445 s | 6.070 s |
| p95 inference | 7.223 s | 6.312 s |
| Mean inference | 6.659 s | 6.109 s |
| Private memory after runs | 19,626 MiB | 19,621 MiB |
| Peak private memory | 19,698 MiB | 19,693 MiB |

The first-run session time is not a usable startup metric because it includes the
network download. The cached-weight session load is about 4.94 seconds.

On this machine, `onnxruntime` exposed `AzureExecutionProvider` and
`CPUExecutionProvider`; DirectML was not available. No DirectML performance was
measured.

The synthetic mask covered 32.318% of the image. Isolated CPU inference takes over
six seconds, so running it on the Qt UI thread is not acceptable. The next
implementation boundary must keep model loading and inference off the UI thread
and preserve an immediate original-image fallback.

## Reproduction

```powershell
  --runs 5 `
  --warmup 1 `

  --json-output .cache\ai-spike\synthetic-metrics.json
```
